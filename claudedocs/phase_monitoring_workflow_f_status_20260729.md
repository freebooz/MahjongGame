## 本轮压测发现并修复的问题

1. Admin、Auth、Lobby 镜像遗漏共享 Observability 项目，导致容器内编译失败。
2. Admin SDK 镜像没有 Node.js，Angular 发布目标失败；已改为 Node 24 多阶段构建。
3. 压测脚本把“请求/秒”错误实现为“迭代/秒”，实际放大 3–4 倍并触发安全限流。
4. 玩家每页查询曾扫描全部一万房间；改为 `active_player_rooms` 批量关联。
5. 玩家 SSE 曾每 5 秒全量扫描十万玩家；改为跨周期分片扫描。
6. 房间 API 曾在每个请求中扫描一万房间；改为 Lobby 数据库原生分页。
7. SSE 首轮曾可能倾倒全量实体；改为首轮只建立哈希基线。

## 后续深化建议

当前实现满足首期容量门禁，但建议下一阶段继续：

1. 使用 Redis Streams、Kafka 或 NATS JetStream 承载跨 Admin 副本事件日志，避免跨副本重连必须全量重同步。
2. Auth 与 Lobby 直接发布账号、会话、在线和房间变更事件，替代玩家目录滚动扫描，把玩家变化检测延迟稳定在 5 秒内。
3. 为房间筛选增加专用表达式索引或物化投影；当前模糊搜索在极端查询下仍可能退化。
4. 在独立压测节点执行 5–15 分钟阶梯负载，并将 Prometheus、PostgreSQL、Redis、容器和浏览器 Performance 数据自动归档。
5. 增加 20,000 Dedicated Server 实例的合成数据和多 Admin 副本故障切换压测。
6. 对 SSE 慢消费者、20,000 事件超窗和浏览器长时间运行执行 2–8 小时 soak test。
